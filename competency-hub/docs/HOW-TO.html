ESG Competency Hub – Releases 1 to 3

This package brings the Hub from app 0.3.0 and solution 1.2.0.0 (what you have now) to app 0.7.0, solution 1.5.0.0 and Setup 1.2. Each release includes the ones before it, so you can install this package directly. Updated 23 October 2026.

  • Release 1, safety net: a queue monitor that recovers stalled changes and retries emails; clear messages while a change is waiting, being recorded, being retried or needs an administrator; an Administration page; and a reduced mode in which the buttons that send changes are paused while changes can't be processed.
  • Release 2, administration and permissions: add people, choose their areas, meeting rights, access end dates and notice posting from the app; the corrected technician and meeting rights; Feedback list and Meeting Minutes library ready for later releases.
  • Release 3, noticeboard, register, feedback, settings and dashboard: read a notice in full, comment, flag it for the next meeting; edit, pin and archive notices; improvements and degradations with linked actions; a Feedback button on every page with a review tab for administrators; a Settings tab; and a Management page for Team Leaders and the Group Head.

Everything here was built and tested on a simulated SharePoint site only. Each part below changes your Competency Hub site or your Power Automate environment, so do it only when you are ready. Nobody else gets access until you add them.

Part A – Setup 1.2 (about 15 minutes)

Setup only adds things; it removes no data. It adds the Feedback list, the Meeting Minutes library, a few new columns and settings, and the group Competency Hub – Notice Posters. It makes one permission change: the Noticeboard goes from "All Users can add" to "All Users can read, Notice Posters can add", so an administrator can stop one person posting. You are the only user, so nobody else is affected.

  1. Upload both files from 1-Setup to Welcome Web Part - Custom Layouts (Replace).
  2. Create the HubSetup page again with a Welcome web part, choose the layout Competency Hub Setup, and publish it.
  3. Click Check. It writes nothing. Send me the log.
  4. When I have looked at it, click Apply, type SETUP and wait for it to finish. Send me the log.
  5. Delete the two Setup files and the HubSetup page again.

Part B – solution 1.5.0.0 (about 10 minutes)

  1. In Power Automate, same environment: Solutions → Import solution → Browse, choose ESGCompetencyHub_1_5_0_0_unmanaged.zip, Next. It should say upgrade.
  2. Keep the SharePoint and Outlook connections and the site address, then Import.
  3. Open the solution. There are now five flows. Make sure all five are On:
    • ESG Competency Hub | 1 Daily tasks and 2 Request queue (already on);
    • ESG Competency Hub | 3 Queue monitor, 4 Records and 6 Administration (new: turn them on).

Part C – app 0.7.0

  1. Upload both files from 3-App to Welcome Web Part - Custom Layouts (Replace).
  2. On the Hub page, edit the web part, Reset layout cache, Republish, and reload with Ctrl+F5. The footer should say 0.7.0.

  5. Your name at the top should read Joseph Pepper, first name first.

Part D – try the safety net (Release 1)

  1. On the home page, click Open Administration. The first card should say Automatic processing is working once the queue monitor has run (within 15 minutes in working hours).
  2. Turn 2 Request queue Off. Raise a TEST action. It shows waiting to be recorded.
  3. Within about 25 minutes the monitor notices that nothing is being picked up. The app then shows a banner saying changes can't be processed, and pauses the buttons that send changes. That is expected: it is what staff would see.
  4. Turn 2 Request queue back On. Within 15 minutes the monitor sends the request again, the action appears without you doing anything else, and the banner goes at the next check.
  5. Send me a screenshot of the Administration page and the run history of 3 Queue monitor.

The same banner appears if the monitor itself stops. Reading and adding updates always keep working. If only 6 Administration is off, staff carry on as normal and the Administration page says so.

Part E – administration and the permission probe (Release 2)

This needs one ordinary account that is not a site owner, for example a test account from IT or a colleague for one session. A site owner can't be used: owners bypass permissions, so every check would pass without proving anything.

Add the test account

  1. Administration → People → Add people. Enter the test account's email, role Technician.
  2. Tick Flask as a member (leave Can run meetings off), and tick Green Stream with Can run meetings on. Leave Can post notices on. Click Add this person; it shows Done and verified after a minute or two.
  3. Open your own name in the list: it should say you can't change your own access.

Run the probe as the test account

  1. As yourself: upload both files from 4-Permission-probe to Welcome Web Part - Custom Layouts, create a page HubProbe2 with a Welcome web part, choose the layout Competency Hub probe P2, and publish it.
  2. Sign in as the test account (a private browser window is easiest) and open the HubProbe2 page.
  3. Click Run read checks, then Run write checks. The write checks wait for the flow, so allow up to 10 minutes. They add one TEST notice and up to two TEST requests, all marked as test records. The second request raises a TEST action for a Team Leader, so that person (you, if you're the first one listed) gets an "assigned to you" email.
  4. Copy everything in the results box and send it to me. The box hides names, email addresses and the site address.
  5. Then, as yourself: in People, open the test account and turn Can post notices off, Save changes. Run the write checks again as the test account and send the results; the notice check should now show it is refused.

Tidy up

  1. Delete the probe files and the HubProbe2 page.
  2. Keep the test account until we've read the results. Then, in People, open it and choose Mark as left.

Part F – notices, the register, feedback, settings and the dashboard (Release 3)

All of this can be tried as yourself. Use TEST in titles so the clean-up in Release 6 can find them.

Notices and comments

  1. On the home page, open Flask. The middle column, Notices & issues, now lists notices and open improvements and degradations. Click a notice: it opens in full.
  2. Add a comment. It appears at once.
  3. Click Flag for the next meeting, then Withdraw the flag. Both are immediate; Discussion history lists them.
  4. Click Pin, then Edit and change the title. Each shows being recorded and then the change, usually within two minutes.
  5. On a comment, click Hide. It disappears once recorded.

Improvements and degradations

  1. In the Flask panel, click Raise an issue. Choose Degradation, give a TEST title and description, choose who is responsible, and send it. It appears in the list within two minutes as REG-0000n.
  2. Open it. Click Raise a linked action and raise a TEST action: it is listed under Linked actions. Or click Link an existing action.
  3. Click Change status, choose Resolved: it asks for an outcome. Enter one and save.
  4. The full area page has the same lists under Notices & issues, with a filter for the register.

Feedback, settings and the dashboard

  1. Click Feedback at the bottom right of any page, send a TEST question, and wait for Thanks – your feedback has been sent.
  2. Administration → Feedback: your item is listed. Open it, write a response, set it to Answered.
  3. Administration → Settings: change Due soon from 7 to 10 days and back. Each change is recorded within a few minutes; try 40 to see it refused.
  4. Management (in the top bar): click any number. The list underneath is exactly the actions that number counts.
  5. Send me screenshots of the notice, the entry and the Management page.

If 4 Records is off, actions carry on as normal; changes to notices and the register are paused and the Administration page says so. Comments and flags still work, because they don't go through a flow.
