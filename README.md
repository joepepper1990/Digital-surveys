  schemas/         JSON Schemas for every register

## Getting started

```bash
tools/bootstrap.sh                    # .NET 10 runtime + pac 2.11.2, pinned
pip install -r tests/requirements.txt
tests/run_all.sh                      # self-tests, then the suite
```

With a baseline package available:

```bash
cp ESGDigitalRadiologicalSurveys_1_1_0_5_FINAL_UNMANAGED.zip source-original/
tools/unpack.sh source-original/ESGDigitalRadiologicalSurveys_1_1_0_5_FINAL_UNMANAGED.zip
tests/run_all.sh                      # produces the real defect inventory
# ... make changes under source-working/canvas ...
tools/pack.sh 1.1.0.6
```

`tools/pack.sh` re-extracts and re-unpacks its own output before reporting
success, so a ZIP with the right filename and a corrupt payload cannot pass.

## The validation suite

`tests/run_all.py` reports four outcomes, and they are not interchangeable:

| Outcome | Meaning |
|---|---|
| **ERROR** | The build should not be released. |
| **WARNING** | A human must decide. |
| **BLOCKED** | The check could **not run** — a controlled source was not supplied. **Not a pass.** |
| **INFO** | Recorded for the build record. |

Current state against the delivered 1.1.0.6 payload: `errors 0  warnings 91
blocked 4  info 6`. The four blocked checks are the four controlled registers,
which were still not supplied. Of the 91 warnings, 86 are findings against
controls that are hard-coded `Visible: =false` — the retired single-instrument
architecture, proven unable to run and left in place per §18; the rest are the
single-screen control budget and the RWP branch that needs `rwp-config.json`.

Static analysis proves nothing about Canvas runtime behaviour.
`STUDIO VERIFICATION REQUIRED` applies to every build.

### Detecting defect classes, not defect instances

The directive lists three confirmed defects (4.1, 4.2, 4.3) that are one class:
*a control presenting instrument X derives its state from instrument Y*. `R001`
detects that class in three shapes, and the tests prove it fires on an
instrument pair that appears nowhere in the directive. Fixing the three known
formulas would not have caught the fourth.

The two defects confirmed in Power Apps Studio on 1.1.0.5 are two more classes,
and `R014`–`R019` detect them the same way: `R014`–`R016` for controls that
collide, leave the canvas or are too small to hit with a glove; `R017`–`R019`
for a screen that renders blank because its content is gated on state nothing
ever writes. `R020` reports how much of the layout was actually evaluable, so a
silent geometry result is never mistaken for a verified one.

`tests/fixtures/defective/` reproduces the shape of every confirmed defect.
`tests/fixtures/clean/` is its corrected counterpart, and doubles as the
reference pattern for the redesigned capability card.
`tests/fixtures/runtime-defective/` and `runtime-clean/` do the same for the
two Studio-confirmed runtime defects.

See [`tests/README.md`](tests/README.md) for the full rule list.

## Controlled facts

Radiation thresholds, the point register, the instrument register, RWP
configuration and map geometry are **controlled facts**. They are never
invented, defaulted or guessed. Where one is missing, configuration records
`SOURCE_REQUIRED` and the suite reports BLOCKED.

Every outstanding item is tracked in
[`docs/CONTROLLED_SOURCE_MATRIX.md`](docs/CONTROLLED_SOURCE_MATRIX.md).
